## Native training and export

The native three-layer, approximately 14.23B-parameter draft initialized from
the released MTP weights. FULL_SHARD, CPU FP32 optimizer states, batch size one
per rank, accumulation one, four anchors, two-block objective chunks and
objective checkpointing fit the validation. Peak allocated CUDA memory was
38.33 GiB on each rank. The matching bounded recipe is
[`deepseek-v41-flash-smoke.yaml`](../../examples/configs/offline/colocated/deepseek-v41-flash-smoke.yaml).

| 2 | 0.81867462 | 3.93257165 | 0 |

There were two optimizer calls, one with nonzero learning rate. All sixteen
windows were consumed exactly once across eight ranks, verified by input hashes.
All checkpoint values were finite; all three FP32 routers changed; fixed router
biases stayed equal; all Adam counters were two. On every rank, the frozen target
embedding/head hashes matched before and after training, their parameters were
excluded from the optimizer, and their gradients remained absent.

Native export verified all 2,401 MTP tensor shapes and source formats, finite
floating tensors/scales and exact trained-router equality. Fifteen MTP overlay
shards totalled 7,933,126,448 bytes. Unchanged target shards were shared by
symlink. This short run establishes the training/export path, not convergence.

## Cached startup and speculative inference

PR #6's exact launcher was applied before SGLang imports; its eight CPU
subprocess regression tests passed. Both DeepGEMM cache variables pointed to
the populated SGLang cache. GPU logs confirmed 3,072 prewarm iterations per
kernel group rather than the previous 65,536. MHC prewarm compilation was about
4–5 seconds per rank with cache reuse, compared with 357–398 seconds on first
capture startup. Process readiness took 1,230 seconds on the first PR #6
inference run and 660 seconds on its subsequent diagnostic run. Cached state
and serving mode differ between runs, so these timings do not isolate PR #6's
speedup. Readiness allowed 5,400 seconds; job deadlines were 14,400 seconds.

The exported model loaded and ran DSPARK block size five. Two greedy 32-token
prompts were each repeated twice in the same diagnostic service:
